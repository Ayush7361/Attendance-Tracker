## 1. System Architecture Overview

The application is built as a decoupled Full-Stack Web Application using the **MERN** stack (MongoDB, Express, React, Node.js).

```mermaid
flowchart TD
    subgraph Frontend ["Frontend (Vite + React)"]
        UI[Pages & Components]
        State[AuthContext & React State]
        Axios[Axios Instance / API Layer]
        UI --> State
        State --> Axios
    end

    subgraph Backend ["Backend (Node.js + Express)"]
        Server[server.js & Router]
        AuthMW[authMiddleware JWT Check]
        Controllers[Controller Logic]
        Server --> AuthMW
        AuthMW --> Controllers
    end

    subgraph Database ["Database (MongoDB + Mongoose)"]
        Models[(Mongoose Models)]
        Controllers --> Models
    end

    Axios <-->|REST API + HttpOnly JWT Cookies| Server
```

## 2. Backend Codebase Deep Dive (`/backend`)

### Core Entry & Configuration

#### [server.js](file:///Users/ayushranjan/attendance-tracker/backend/server.js)
- **Function**: Express server entry point.
- **Key Responsibilities**:
  - Initializes CORS (configured for `http://localhost:5173` with `credentials: true` for cookies).
  - Connects to MongoDB via `connectDB()`.
  - Configures `express.json()` and `cookie-parser` middleware.
  - Mounts REST API routes under `/api/auth`, `/api/schedule`, `/api/days`, `/api/months`, `/api/deadlines`, `/api/semester`.

#### [config/db.js](file:///Users/ayushranjan/attendance-tracker/backend/config/db.js)
- **Function**: Database connection handler.
- **Key Logic**: Uses `mongoose.connect(process.env.MONGO_URI)` to establish connection with error catching.

#### [middleware/authMiddleware.js](file:///Users/ayushranjan/attendance-tracker/backend/middleware/authMiddleware.js)
- **Function**: Authentication protection middleware.
- **Key Logic**: Extracts JWT token from incoming request cookies (`req.cookies.token`). Verifies token signature using `process.env.JWT_SECRET` and attaches `req.userId = decoded.userId`. Returns HTTP 401 if token is missing or invalid.

### Database Models (`/backend/models`)

1. **[User.js](file:///Users/ayushranjan/attendance-tracker/backend/models/User.js)**
   - **Schema**: `username` (string, unique), `password` (hashed string).
   - **Function**: Represents registered users.

2. **[Schedule.js](file:///Users/ayushranjan/attendance-tracker/backend/models/Schedule.js)**
   - **Schema**: `userId` (Ref: User), `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun` (Arrays of subject names).
   - **Function**: Stores the user's weekly timetable configuration.

3. **[DayRecord.js](file:///Users/ayushranjan/attendance-tracker/backend/models/DayRecord.js)**
   - **Schema**: `userId`, `date` (ISO Date), `year`, `month`, `day`, `dayOfWeek`, `records` (Array of `{ subject, status: "attended" | "missed" }`).
   - **Function**: Records actual daily attendance logs.

4. **[Deadline.js](file:///Users/ayushranjan/attendance-tracker/backend/models/Deadline.js)**
   - **Schema**: `userId`, `title`, `subject`, `dueDate`, `type` ("Assignment", "Exam", "Project", "Other"), `completed` (boolean), `subtasks` (Array of `{ title, completed }`), `notes`.
   - **Function**: Manages student tasks, subtask checklists, and due dates.

5. **[SemesterEvent.js](file:///Users/ayushranjan/attendance-tracker/backend/models/SemesterEvent.js)**
   - **Schema**: `userId`, `title`, `date`, `type` ("Semester Event", "Exam", "Important Date", "Break", "Other").
   - **Function**: Stores academic calendar dates, exam schedules, and semester events.

6. **[LegacyMonthRecord.js](file:///Users/ayushranjan/attendance-tracker/backend/models/LegacyMonthRecord.js)**
   - **Schema**: `userId`, `year`, `month`, `totalClasses`, `attendedClasses`.
   - **Function**: Maintained for legacy monthly summary records.

### Controllers & Business Logic (`/backend/controllers`)

1. **[authController.js](file:///Users/ayushranjan/attendance-tracker/backend/controllers/authController.js)**
   - `register`: Hashes passwords using `bcryptjs`, creates user, sets HttpOnly JWT cookie.
   - `login`: Validates user credentials, sets HttpOnly JWT cookie on success.
   - `logout`: Clears the HttpOnly JWT cookie.
   - `getMe`: Returns currently authenticated user details.

2. **[scheduleController.js](file:///Users/ayushranjan/attendance-tracker/backend/controllers/scheduleController.js)**
   - `getSchedule`: Retrieves weekly subject schedule for logged-in user.
   - `saveSchedule`: Upserts (creates or updates) weekly subject schedule.

3. **[dayController.js](file:///Users/ayushranjan/attendance-tracker/backend/controllers/dayController.js)**
   - `saveDayRecord`: Logs or updates attendance for a specific calendar date.
   - `getDayRecord`: Retrieves logged attendance for a specific date.
   - `deleteDayRange`: Deletes day records within a start/end date range.
   - `resetAll`: Permanently deletes all logged attendance history for user.

4. **[monthController.js](file:///Users/ayushranjan/attendance-tracker/backend/controllers/monthController.js)**
   - `getMonthSummary`: Aggregates total and attended class counts for a given month and year.
   - `getOverallSummary`: Aggregates total and attended class counts across all time.

5. **[deadlineController.js](file:///Users/ayushranjan/attendance-tracker/backend/controllers/deadlineController.js)**
   - `getDeadlines`: Returns list of deadlines filtered by type/subject and sorted by due date.
   - `createDeadline` / `updateDeadline` / `deleteDeadline`: CRUD operations for deadlines and subtasks.
   - `toggleDeadline`: Quick toggle for completing a deadline.
   - `getAnalytics`: Calculates deadline stats (total, completed, pending, completion rate %, status breakdown: overdue, dueToday, thisWeek).
   - `getSubjects`: Returns unique list of subject names used across user's deadlines.

6. **[semesterController.js](file:///Users/ayushranjan/attendance-tracker/backend/controllers/semesterController.js)**
   - `getEvents`: Fetches academic events sorted by date.
   - `createEvent`: Adds a new semester event, exam, or key date.
   - `deleteEvent`: Removes an academic event.

## 4. End-to-End Execution Flow Summary

1. **User Login**: User submits username & password -> `authApi.loginUser()` -> POST `/api/auth/login` -> Password validated with `bcryptjs` -> HttpOnly JWT cookie set in browser -> User redirected to `/`.
2. **Dashboard Navigation**: User lands on `/` (`Hub.jsx`) with digital grid background -> Selects module (Attendance, Deadlines, or Academic Timeline).
3. **Attendance Logging**: User selects date on `AttendanceCalendar` -> Day schedule auto-populates from `ScheduleForm` timetable -> User checks attended/missed classes -> POST `/api/days` -> Summary automatically recalculates monthly percentage.
4. **Deadlines & Analytics**: User creates deadline with subtasks -> POST `/api/deadlines` -> Express saves `Deadline` model -> `getAnalytics()` dynamically aggregates completion percentages and status counts.
